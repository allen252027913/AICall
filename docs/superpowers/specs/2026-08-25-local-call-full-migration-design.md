# 独立本地 AI 通话完整能力迁移设计

## 1. 背景与目标

将 `tmallandroid_messagebox` 的 `feature/dev_AI_call` 分支中已经实现的本地 AI 通话能力，迁移到独立 Android 工程 `DoubaoLocalCallDemo`。

目标工程已经具备 Compose 页面、sherpa-onnx 流式语音识别、系统 TTS、MediaProjection 截屏和 PP-OCRv5 端侧 OCR。本次以目标工程为主干增量迁移，不覆盖其现有 OCR、NDK 和 Gradle 构建链。

迁移完成后，Demo 应能独立构建和运行，不依赖天猫宿主类、账号体系或 MTop 签名环境。

## 2. 迁移范围

### 2.1 通话与语音交互

- 前台服务持续保活、常驻通知与 WakeLock。
- sherpa-onnx 连续流式识别及 endpoint 断句。
- 没有命中意图时保持安静，不重复播报。
- 命中意图后立即播报确认语，再执行后续操作。
- TTS 播放期间仅“先停一下”能够中断，其他识别内容不打断当前播报。
- 画中画开关和扬声器声音输入开关。
- 扬声器输入沿用现有语义：普通麦克风源关闭回声消除和降噪，使公放声音可通过麦克风被识别；不实现数字音频内录。

### 2.2 屏幕共享与内容理解

- MediaProjection 用户授权与会话管理。
- 根据语音意图按需获取当前屏幕 Bitmap。
- 截图失败时最多重试三次。
- 截图前使用保护时间和可见性协调，降低画中画被截入关键帧的概率。
- 使用目标工程现有 PP-OCRv5 识别关键帧。
- 在通话页展示关键帧、OCR 内容和来源应用包名。
- 记录前台窗口和应用变化，用于标注内容来源。

### 2.3 画中画

- 用户离开通话 Activity 时按开关决定是否进入画中画。
- 没有图片时使用紧凑文字画中画。
- 首张关键帧产生后切换为适配手机纵向比例的图文画中画。
- 画中画中只展示关键帧和 OCR 内容。
- 返回本应用时退出画中画。

### 2.4 图文历史与结果页

- 每次有效识别后，将压缩图片、OCR、来源包名和时间写入应用私有缓存。
- 空图片、空识别或最终失败不创建历史项。
- 返回本应用时，如在外部应用产生了新内容，则导航到结果页。
- 结果页以 Compose 图文 Feed 展示历史记录。
- 通话页提供主动进入结果页的入口。

### 2.5 商品识别

- 支持语音“帮我看一下这个商品”。
- 保留当前帧编码、图片尺寸、请求参数模型、响应解析和首个商品名称/价格播报格式。
- 使用 `ProductRecognitionGateway` 隔离真实服务。
- 独立 Demo 默认实现明确返回“未配置商品识别服务”，不伪造结果、不增加网络权限。
- 后续可通过注入 MTop 实现恢复真实接口调用，不修改通话主流程。

### 2.6 通用无障碍操作

- 通话页提供打开无障碍设置的入口和当前授权状态。
- 支持语音控制上滑、下滑、左滑、右滑。
- 支持按第 N 个列表项进行查找和点击。
- 支持按当前文本内容查找并点击按钮。
- 点击顺序为 View ID、目标节点或最近可点击祖先，无法定位时返回失败说明。

### 2.7 京东自动化

- 语音“去京东打卡”触发独立状态机。
- 检查京东是否安装和无障碍是否开启。
- 打开京东并依次执行“我的 → 更多 → 一键领取”。
- “更多”未找到时使用兜底坐标 `[916, 475]`。
- “一键领取”未找到时使用兜底坐标 `[500, 574]`。
- 每一步 Toast 明确说明使用 View ID、无障碍节点/祖先或固定坐标完成点击。
- 页面变化、超时或失败时结束当前流程，避免重复误触。

## 3. 总体架构

采用独立原生迁移方案：保留目标工程的 Compose 和 OCR/NDK 技术栈，将源工程业务能力适配到 `me.fleey.ppocrv5.call` 命名空间。禁止引入 `TMActivity`、天猫自定义 View、MTop、fastjson 或其他天猫宿主依赖。

主要组件：

- `MainActivity`：权限、MediaProjection 授权、画中画生命周期和页面导航。
- `CallScreen`：通话状态、开关、权限入口、关键帧和 OCR 展示。
- `ResultScreen`：历史图文 Feed。
- `VoiceCallService`：前台保活、识音、意图、操作调度和 TTS。
- `LocalCallTurnCoordinator`：确认语、异步操作结果和最终播报的顺序协调。
- `LocalCallTurnPolicy`：查看屏幕、商品识别、京东打卡和停止播报意图。
- `ScreenCaptureEngine`：MediaProjection 和 Bitmap 获取。
- `ScreenCaptureRetryPolicy`：三次重试与间隔。
- `PpOcrScreenAnalyzer`：目标工程现有 PP-OCRv5 适配器。
- `CaptureHistoryRepository`：图片文件和元数据缓存。
- `PictureInPictureController`：紧凑/图文模式及比例选择。
- `LocalCallAccessibilityService`：窗口感知、手势、节点遍历和点击。
- `JdAutomationController`：京东跨页面自动化状态机。
- `ProductRecognitionGateway`：商品识别服务边界。

## 4. 核心数据流

### 4.1 通话启动

1. Activity 获取录音和通知权限。
2. 用户主动授权 MediaProjection。
3. Activity 启动前台服务并传递授权结果。
4. 服务初始化 OCR、ASR、TTS、WakeLock 和屏幕捕获会话。
5. UI 通过共享状态订阅服务状态。

### 4.2 语音轮次

1. ASR partial 仅用于 UI 展示及检测“先停一下”。
2. endpoint 产生最终文本后执行意图匹配。
3. 未匹配则清空当前 partial，不播报。
4. 匹配后创建唯一轮次 token，立即播放确认语，同时异步执行操作。
5. 确认语和操作可能以任意顺序结束，由协调器保证最终结果只播放一次。
6. 过期 token 的回调全部丢弃，防止旧任务覆盖新轮次。

### 4.3 查看屏幕

1. 等待画中画避让保护间隔。
2. 尝试读取 Bitmap，失败时按策略重试，最多三次。
3. OCR 生成文本块和摘要。
4. 读取最近前台窗口包名并形成记录。
5. 原子更新当前关键帧、历史仓库和 UI。
6. 播报 OCR 摘要；全程失败时只播报一次错误。

### 4.4 无障碍自动化

1. 服务根据 `AccessibilityEvent` 更新当前包名、窗口和根节点。
2. 通用命令执行全局手势或深度优先节点查找。
3. 京东命令由状态机等待目标页面稳定，再寻找当前步骤目标。
4. 优先点击可验证的控件，最后使用步骤专属坐标。
5. 每步完成后发出结果事件和 Toast，并进入下一状态。

## 5. 状态与存储

- 通话瞬时状态保存在进程内 `StateFlow`，不持久化 MediaProjection Intent。
- 用户偏好使用 `SharedPreferences` 保存。
- 历史图片存入 `cacheDir/local_call_history/images`。
- 历史元数据使用应用私有 JSON 文件，采用原子临时文件替换写入。
- 限制历史数量和磁盘占用，淘汰时同时删除图片与元数据。
- Bitmap 在完成压缩或 UI 替换后及时回收引用，避免长期持有全尺寸屏幕。

## 6. 权限与隐私

- 只在用户明确点击开始通话后申请录音和屏幕共享。
- 前台服务始终展示系统通知。
- MediaProjection 停止后立即释放 VirtualDisplay 和 ImageReader。
- 无障碍能力由用户在系统设置中单独开启。
- Demo 不上传屏幕图片；默认商品识别网关不发起网络请求。
- 历史仅保存到应用私有缓存，可随应用缓存清理。

## 7. 错误处理

- 权限拒绝：保持页面可用，指出缺失权限并提供再次申请入口。
- MediaProjection 失效：停止取帧并提示重新授权。
- OCR 初始化或执行失败：释放当前 Bitmap，返回一次错误，不写历史。
- ASR/TTS 初始化失败：进入错误状态并允许重新开始通话。
- 无障碍未开启、京东未安装或页面超时：终止自动化并给出具体提示。
- 坐标兜底只用于已经明确配置的京东步骤，不对未知页面通用点击。
- 商品识别未配置：播报服务未配置，不影响查看屏幕和其他能力。

## 8. 测试设计

### 8.1 单元测试

- 屏幕意图、商品意图、京东意图和停止意图匹配。
- TTS 播放期间非停止话语不会中断。
- 确认语和操作结果乱序完成时仍只播报一次结果。
- 三次截图重试的成功、耗尽和异常路径。
- 画中画紧凑/图文模式及宽高比策略。
- 历史记录写入、读取、淘汰和损坏数据恢复。
- 无障碍深度优先遍历、可点击祖先和 View ID 优先级。
- 京东状态转换、超时和两个坐标兜底。
- 商品识别默认网关不会发起网络请求。

### 8.2 构建与静态检查

- `./gradlew testDebugUnitTest`
- `./gradlew assembleDebug`
- `./gradlew lintDebug`

### 8.3 真机验收

- Android 9、Android 13 和 Android 15 各覆盖一台设备或对应系统版本。
- 验证后台保活、通知、锁屏/解锁、系统回收后的行为。
- 验证授权后进入外部应用、画中画形态切换、关键帧 OCR 与结果 Feed。
- 验证截图失败后的三次重试。
- 验证 TTS 只被“先停一下”中断。
- 验证开关对下次通话和重新启动后的状态影响。
- 验证无障碍通用手势、文本点击和京东完整链路。

## 9. 非目标

- 不绕过 Android 的 MediaProjection 或无障碍授权。
- 不保证系统合成截图一定能排除画中画，只通过时序和可见性策略降低出现概率。
- 不实现真实 MTop 网络调用、天猫账号登录或签名。
- 不实现系统播放音频的数字内录。
- 不为京东之外的应用提供硬编码坐标兜底。

## 10. 完成标准

- 目标工程独立编译，不依赖天猫内部 Maven 仓库或宿主类。
- 本文迁移范围中的页面、服务、取帧、OCR、画中画、历史、语音策略和无障碍能力均可访问。
- 单元测试、Debug 打包和 lint 通过。
- 真机权限路径和关键业务链路具备明确的人工验证清单。
