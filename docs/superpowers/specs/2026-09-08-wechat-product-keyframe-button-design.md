# 微信商品关键帧按钮设计

## 目标

在本地 AI 通话页提供一个独立按钮。用户开始通话、开启屏幕共享并授权无障碍服务后，点击按钮即可自动打开微信，依次完成搜索“李佳琦”、进入“所有女生会员服务中心”、进入“直播预告”、选择“09”、打开该日期下方 Feeds 流中的第一个商品，并在商品页面稳定后截取、识别和保存当前屏幕关键帧。

## 范围

本功能只新增按钮触发的单条固定自动化流程，并复用现有通话、MediaProjection、无障碍指令租约、OCR 和识别记录能力。

包含：

- 通话页按钮及其启用条件。
- 微信 App 启动和分阶段无障碍操作。
- 页面刷新、跳转等待、重试、超时和取消。
- 商品详情页关键帧截取、OCR、当前关键帧更新和历史记录保存。
- JVM 单元测试、Android 构建检查和真机验收步骤。

不包含：

- 配置任意搜索词、日期或公众号名称。
- 绕过微信登录、系统授权或验证码。
- 使用固定机型坐标作为主要定位方案。
- 修改微信或直播业务自身实现。
- 将截图或识别内容上传到网络。

## 方案选择

采用“显式按钮入口 + 可取消的无障碍状态机 + 现有屏幕共享截帧”方案。

未采用一次性脚本串行点击，因为页面加载速度变化时容易误点，且无法与通话结束、屏幕共享撤销或用户中断正确竞争。未采用纯坐标点击，因为不同屏幕尺寸、字体缩放和微信版本会改变控件位置。目标定位以无障碍节点的文本、内容描述、可编辑性和屏幕范围为准；只有项目现有能力已经定义并可安全约束的手势才可作为局部补充，不引入裸坐标主流程。

## 交互入口

通话页显示“微信商品关键帧”按钮，放在无障碍授权入口之后、手动问题输入区之前。

按钮仅在以下条件同时成立时可用：

- 通话处于活动状态。
- 屏幕共享已授权且仍在运行。
- 本应用的无障碍服务已启用。
- 通话当前处于可接收新任务的 `LISTENING` 阶段，而不是处理或播报阶段。

点击按钮向 `VoiceCallService` 发送专用 action。服务将按钮事件映射成 `WECHAT_PRODUCT_CAPTURE`，沿用现有 turn、token 和 automation lease，避免按钮入口绕过通话任务的取消与并发约束。任务忙碌时不启动第二条自动化，并返回明确提示。

## 自动化状态机

每次执行持有唯一正整数 token。只有仍持有有效租约的事件才能产生点击、输入、状态迁移或 Toast，过期事件不能继续操作其他 App。

状态和动作如下：

1. `OPEN_WECHAT`：通过包名 `com.tencent.mm` 获取启动 Intent。启动成功后进入顶部搜索阶段。
2. `OPEN_TOP_SEARCH`：在微信根节点中寻找文字或内容描述精确归一化为“搜索”的节点，点击其自身或最近的可点击祖先。
3. `ENTER_QUERY`：寻找已启用且可编辑的输入节点，通过 `ACTION_SET_TEXT` 输入“李佳琦”。
4. `SUBMIT_SEARCH`：再次查找当前页面中精确标记为“搜索”的提交节点并点击。
5. `OPEN_SERVICE_CENTER`：等待搜索结果刷新，点击“所有女生会员服务中心”。
6. `OPEN_LIVE_PREVIEW`：等待页面跳转，点击底部“直播预告”。
7. `SELECT_DAY_09`：等待页面跳转，点击顶部“09”。
8. `OPEN_FIRST_PRODUCT`：等待日期内容刷新，以“09”节点底边作为上方锚点，在其下方可见区域查找第一个有效 Feeds 商品容器并点击。
9. `WAIT_PRODUCT_DETAIL`：点击后等待商品详情页稳定，不再执行无障碍点击。
10. `COMPLETE`：释放无障碍任务，并通知通话服务执行一次关键帧截取。

“第一个商品”指无障碍树深度优先顺序中，第一个同时满足以下条件的候选：位于当前“09”节点下方、具有有效高度、仍在主要可见区域内，并且自身是列表项或可点击节点。点击仍通过自身或最近可点击祖先完成。

## 页面等待与容错

所有可操作阶段采用有限重试，而不是单次查找失败后立即结束：

- 普通节点暂未出现时，短延迟后重新读取当前活动窗口。
- 搜索提交和日期“09”点击后使用更长的内容刷新等待。
- 页面跳转后使用页面过渡等待。
- 商品点击后使用详情稳定等待，然后再触发截帧。
- 每个阶段独立计时，超过阶段时限则结束；外层通话服务的截止时间覆盖完整状态机预算。

以下情况必须停止且不继续点击：

- 微信未安装或无法启动。
- 屏幕共享未开启或执行中被撤销。
- 无障碍服务未启用、被中断或销毁。
- 活动窗口不再属于微信并持续至超时。
- token 被取消、通话结束或已有其他无障碍任务占用租约。
- 输入或目标节点在阶段时限内始终不可用。

每条结束路径只发布一次结果，清理 handler callback、订阅、超时任务和命令租约。

## 关键帧处理

无障碍状态机完成后，`VoiceCallService` 在后台工作线程执行已有安全截帧流程：

1. 再次确认当前 turn 有效且屏幕共享仍开启。
2. 通过画中画可见性协调器等待安全时机并丢弃旧帧。
3. 使用有限重试获取一张新的 `Bitmap`。
4. 使用本地 PP-OCRv5 分析关键帧；未识别到文字时仍保留关键帧，并使用明确的空文本说明。
5. 通过现有提交协调器原子更新当前关键帧并保存识别历史。
6. 回收 Bitmap，完成通话 turn，并播报成功或失败结果。

整个过程不新增网络上传。

## 代码边界

优先复用和完善以下已有单元：

- `CallScreen.kt`：按钮展示和回调。
- `MainActivity.kt`：将按钮回调转换为服务 action。
- `VoiceCallService.kt`：按钮 action、turn 生命周期、自动化结果订阅和最终截帧。
- `LocalCallWeChatAutomationController.kt`：前置条件检查、微信启动和命令入队。
- `WeChatAutomationStateMachine.kt`：阶段、超时和 token 化迁移。
- `WeChatAutomationTargets.kt`：目标文本、输入节点和首个 Feed 候选策略。
- `LocalCallAccessibilityService.kt`：节点遍历、点击、输入、调度与结束。
- `WeChatAutomationResult.kt`：用户可理解的结果文案。

若审计表明这些骨架已经满足某一要求，则保留实现并通过测试固定行为，不进行无关重构。

## 测试设计

自动测试至少覆盖：

- 按钮只在通话、屏幕共享、无障碍均有效时启用。
- 按钮 action 能映射到微信商品关键帧 turn。
- 缺失屏幕共享或无障碍授权时不会启动微信。
- 微信启动成功后命令从顶部搜索阶段开始。
- 正常路径按固定顺序到达详情等待和完成状态。
- 错 token、乱序回调、重复完成不能推进状态。
- 每个可操作阶段可独立超时。
- 目标文本采用去空白后的精确匹配，避免将“搜索结果”当成“搜索”。
- 输入节点必须同时可编辑且启用。
- 首个 Feed 候选必须位于“09”下方并在主要可见区域内。
- 自动化成功后才触发截图；失败只完成 turn，不截图。
- 屏幕共享撤销会使微信自动化失效，失效 turn 不能提交关键帧。

构建验证包含 JVM 单元测试、Debug Kotlin/Java 编译和 Debug APK 组装。最终真机验收需要已登录微信的设备，因为仓库单元测试无法验证第三方 App 的实际无障碍树。

## 验收标准

- 满足三个前置条件时，用户点击一个按钮即可启动完整流程，不需要继续手动操作。
- 自动化严格按指定顺序执行，不跨阶段点击同名节点。
- “09”刷新后打开其下方 Feeds 流中的第一个有效商品。
- 商品页稳定后产生一条新的关键帧记录，并更新通话页当前关键帧。
- 任一权限、页面或生命周期失败均停止自动点击并显示明确结果。
- 自动化测试和 Android Debug 构建通过；真机验收记录实际微信版本及未命中的节点信息（如有）。

## 外部知识核验说明

LiveNexaKB 查询在本次设计阶段仅返回异步受理状态，没有返回 `verified/completed` 结果，因此没有把候选知识表述为已核验事实。AIMI Sidecar 提供的直播预告/商品 Feeds 仓库元数据只用于确认“日期筛选后展示商品流”是合理语义背景；实际实现与验收以当前设备上的微信无障碍节点和本仓库既有契约为准。
